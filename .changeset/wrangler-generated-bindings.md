fix: preserve Wrangler-generated binding types in `CloudflareEnv`

Wrangler can generate required bindings such as `ASSETS` that overlap with the adapter's optional defaults. The overlap caused TS2430 with `skipLibCheck: false` and made configured bindings appear optional. Bindings generated with `wrangler types --env-interface CloudflareEnv` now retain their generated types, and unconfigured bindings keep their optional types.

If your binding declarations were generated by an older Wrangler, regenerate them with the current version using `wrangler types --env-interface CloudflareEnv <existing-declaration-file>`. Workers runtime declarations can still conflict with TypeScript's DOM library when both are loaded.
